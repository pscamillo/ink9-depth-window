# PREREG L1 — does the 2026-08-18 label correction change the model?

**Date:** 2026-08-19
**Sealed:** `32347bcb63cdac9864148f16839d45d1e8f0af4db5fea0742236b32c8b27cee6`
**Inherits** protocol and criterion from `B13.md` onwards.

## 1. The problem

On 2026-08-18 at 11:01 `err` announced that the `ink_9um` masks and labels had
been uploaded **with the alignment pipeline's seam regions masked off**, and
replaced the files in place.

**The five depth-axis arms trained on the earlier version.** Measured on the
full centre slice of all 51 masks:

| mask | segments that moved | relative delta | pixels |
|---|---|---|---|
| `inklabels` | 21/24 | median +0.0%, mean +2.5%, max +21.7% | +318,647 / −29,011 |
| `supervision_mask` | 19/24 | median +0.0%, mean +2.5%, max +21.5% | +1,106,910 / −16,370 |
| `validation_mask` | 1/3 | max +1.7% | +2,924 / −0 |

**Already settled:** the effect on **evaluation**. Our metrics were measured
against the corrected validation masks, and Domenico Russo independently
measured on 2026-08-18 that rescoring the 14 released checkpoints against the
corrected labels moves at most 0.0033 across 61 scorings, mean 0.0002, without
changing the best checkpoint per region.

**Not measured by anyone:** the effect on **training**. Rescoring is cheap and
comes back null; training on different supervision is a different question.

    H_null:   the correction adds supervision in seam regions, which are
              marginal. A model trained on it is indistinguishable from one
              trained without.

    H_effect: the added supervision — up to +21.5% on one segment, concentrated
              on Paris 4 — changes what the model learns, visibly.

**No outcome is uninformative.** Under H_null the limitation declared on the
depth axis resolves empirically. Under H_effect it is a finding for anyone
retraining the recipe, and the whole axis has to be retrained.

## 2. The experiment

One run: **m17L** — identical to **m17** except that it reads the corrected
labels rather than the pre-correction copy.

| arm | labels | window | jitter |
|---|---|---|---|
| m17 | pre-correction (2026-08-15) | 17 slices | ±2 |
| **m17L** | **corrected (2026-08-18)** | 17 slices | ±2 |

One variable: **the labels**. Same architecture, same `patch_size`, same jitter,
same seed 42, same 78,125 iterations, same batch 64, same quotas. The
`NetworkFromConfig` dump is identical, as expected — labels do not touch
architecture.

Estimated cost: ~6 h. The m17 predictions already exist, so only the new arm
needs inference.

## 3. Windows

**The same 60**, with a new A/B assignment (seed 202608191).

**Declared risk:** the judge has assessed these windows five times; memory of
the content is certain.

**Favourable to this one specifically:** unlike the other arms, the judge has
**no directional expectation** — there is no hypothesis about which side should
win, and nothing in the images indicates which label version is which.

Judging criterion as stated from `B5.md` onwards.

## 4. Verdict criterion

Two-sided binomial against p = 0.5 over the decided windows.

| result | verdict |
|---|---|
| m17L wins, p < 0.05 | **H_effect.** The correction improves the model; the depth axis needs retraining on the corrected labels. |
| m17 wins, p < 0.05 | **H_effect, opposite direction.** A strange result that would need its own investigation before any conclusion. |
| p ≥ 0.05, or ties > 60% | **H_null.** The correction does not change the model visibly. |

## 5. What this does not resolve

**5.1 — It does not validate the other four arms individually.** It measures the
effect of the correction **on the 17-slice arm**. If the added supervision
interacted with window depth — if seam regions were systematically shallower or
deeper — the effect could differ on the narrow arms. There is no reason to
expect that, but it is not measured.

**5.2 — One replicate.** Seed 42 only.

**5.3 — Region-held-out validation**, as in the others.

## 6. Confounder

**The effective corpus can change size.** More supervision means more eligible
patches, which changes how often each patch recycles over 78,125 iterations.

Measured after the fact: 133,888 patches against 133,770, **+0.09%**. The added
supervision lands inside patches that already existed rather than creating new
ones, so this confounder turned out to be much smaller than the design allowed
for.
